# پیشنهاد و انتخاب پشتهٔ فناوری

## ۱. معیارهای انتخاب

با توجه به الزامات سازمان (استقرار **On-Premise** در شبکهٔ داخلی، **چند‌شرکتی**، **دیتابیس مرکزی**، **امنیت**، **خروجی Excel/PDF**، **API**، بومی‌سازی فارسی/شمسی و هزینهٔ لایسنس)، معیارهای زیر وزن‌دهی شدند: بلوغ اکوسیستم، سرعت توسعه، مناسب بودن برای داشبورد داده، هزینهٔ مالکیت، سهولت استقرار داخلی، و در‌دسترس بودن نیروی متخصص.

## ۲. مقایسهٔ گزینه‌های Backend

| معیار | **Python/FastAPI** ✅ | ASP.NET Core | Java/Spring Boot |
|-------|:--------------------:|:------------:|:----------------:|
| سرعت توسعه | بسیار بالا | بالا | متوسط |
| اکوسیستم داده/تحلیل | عالی (pandas, openpyxl) | خوب | خوب |
| مستندسازی خودکار API | داخلی (OpenAPI) | Swashbuckle | Springdoc |
| هزینه لایسنس | صفر (متن‌باز) | صفر (Core) | صفر |
| مناسب On-Premise | عالی | عالی (Win/Linux) | عالی |
| منحنی یادگیری | کم | متوسط | زیاد |
| رندر PDF فارسی | reportlab + reshaper | نیازمند کتابخانه ثالث | نیازمند کتابخانه ثالث |

**انتخاب: Python 3.12 + FastAPI** — بهترین توازن سرعت توسعه، اکوسیستم داده (حیاتی برای Import اکسل و گزارش‌گیری)، و تولید خودکار مستندات API.

## ۴. پشتهٔ نمونهٔ اولیه (این مخزن) و تفاوت با تولید

| مؤلفه | نمونهٔ اولیه (خودکفا) | تولید |
|-------|----------------------|-------|
| پایگاه داده | SQLite (بدون نصب) | PostgreSQL (تنها با تغییر `DATABASE_URL`) |
| فرانت‌اند | React 18 از طریق **UMD + htm** (بدون build) | React + Vite + TypeScript |
| نمودار | Chart.js (وندور محلی) | Chart.js/Recharts |
| منطق دامنه | **یکسان** | **یکسان** (بدون تغییر) |

> این جداسازی عمدی است: نمونه بدون هیچ نصب خارجی اجرا می‌شود، اما منطق دامنه، مدل داده و API دقیقاً همان چیزی است که در تولید استفاده می‌شود؛ مهاجرت صرفاً تعویض زیرساخت است، نه بازنویسی.

## ۵. توپولوژی استقرار (On-Premise)

```
[کاربران شبکه داخلی] ──HTTPS──▶ [Nginx + TLS] ──▶ [API: Uvicorn×N (Docker)]
                                                        │
                                                        ▼
                                              [PostgreSQL (Docker/VM)]
                                                        │
                                              [Backup: pg_dump زمان‌بندی‌شده]
```

- استقرار با `docker compose up -d --build`.
- Health-check و Restart-policy برای پایداری.
- جداسازی شبکهٔ دیتابیس؛ دسترسی فقط از سرویس API.

## ۶. ملاحظات امنیتی تولید
چرخش دوره‌ای `KPI_SECRET_KEY`، Rate-limit روی ورود، Security Headers، سیاست رمز عبور قوی، پشتیبان‌گیری رمزنگاری‌شده، و لاگ‌برداری متمرکز. برای هویت سازمانی، افزودن **LDAP/Active Directory یا SSO (OIDC)** در نقشه راه است.

## ۷. نقشهٔ راه فنی
مرحله ۲: Alembic + PostgreSQL + build کامل React. مرحله ۳: اعلان‌ها (ایمیل/پیامک)، Import خودکار اکسل، LDAP/SSO. مرحله ۴: تحلیل پیشرفته و پیش‌بینی روند (ML)، اپ موبایل، امضای دیجیتال.
